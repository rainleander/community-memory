 # Contributing to Community Memory

Thank you for your interest in Community Memory.

This project explores how open-source communities can better preserve, discover, and reuse project knowledge. We're particularly interested in practical examples, real-world pain points, and reusable patterns.

## Ways to Contribute

### Share a Use Case

Tell us about a problem you've encountered:

- A decision that was difficult to find
- Knowledge lost when maintainers moved on
- Repeated contributor questions
- Governance history that became difficult to trace
- Architecture decisions buried in project artifacts

Open an issue and describe the experience.

### Contribute Examples

We're especially interested in examples from established open-source communities.

Examples may include:

- Architecture Decision Records (ADRs)
- Contributor FAQs
- Governance documentation
- Design proposals
- Decision tracking workflows
- Knowledge discovery tools

### Contribute Templates

Help create reusable templates that make project knowledge easier to capture and discover.

Examples:

- ADR templates
- Governance decision templates
- Discussion summary templates
- Contributor FAQ formats

### Experiment with Tooling

Prototype ideas that help answer questions such as:

- Why was this decision made?
- When did this change?
- What alternatives were considered?
- Where was this discussed?

Tooling experiments should prioritize transparency and traceability back to original project artifacts.

## Contribution Guidelines

### Keep It Practical

We prioritize approaches that help real open-source communities.

When possible, include:

- The problem being solved
- How the solution works
- Benefits
- Limitations
- Links to examples

### Prefer Open Standards

Whenever possible:

- Use open formats
- Avoid proprietary dependencies
- Preserve links to original sources
- Ensure information remains portable

### Cite Sources

Community Memory is about making knowledge discoverable.

Please include references to:

- Issues
- Pull Requests
- Discussions
- Documentation
- Design records

whenever they support your contribution.

## Getting Started

1. Read the README.
2. Browse open issues.
3. Share an example, idea, template, or experiment.
4. Open a pull request.

If you're unsure where to start, open an issue describing a project knowledge problem you've encountered.

That's valuable input too.

## Our Philosophy

Community Memory is not attempting to replace maintainers.

It's an ongoing exploration of a simple question:

> How do we ensure community knowledge scales beyond the people who originally created it?
